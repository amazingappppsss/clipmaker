# ClipMaker — Architecture

> Source of truth for structure and conventions. Read before adding code; update it when
> structure changes. Product requirements live in the PRD; this document says **where things go**.

## 1. System overview

```
 Browser (Next.js)                         FastAPI (web API)                  Celery workers
 ─────────────────                         ────────────────                   ──────────────
 landing / app UI  ──JWT──►  /projects, /account, /plans  ──enqueue──► Redis ──► pipeline queue
       │                            │                                              render queue
       │  signed PUT/GET URLs       │ SQLAlchemy                                   │
       ▼                            ▼                                              ▼
 Object storage (R2) ◄─────── PostgreSQL (Supabase) ◄──────────────────── stages read/write
 (videos never pass                                                         FFmpeg / OpenCV /
  through the API)                                                          AI providers
```

* The API **never** processes video synchronously. Uploads go browser → storage directly;
  heavy work runs in Celery workers (separate processes, separately scalable).
* Auth is Supabase Auth. The browser holds the session; every API call carries a bearer JWT
  that the API verifies (JWKS for asymmetric keys, HS256 secret for legacy/dev).

```
    media/                   FFmpeg/FFprobe/OpenCV wrappers (probe, cut, reframe, captions)
    providers/               swappable AI: transcription/, llm/, diarization/  (Milestone 2+)
    storage/                 ObjectStorage protocol + local and S3/R2 implementations
    db/                      models.py, session.py, migrations/ (Alembic)
    workers/                 Celery app + tasks
frontend/                    Next.js 16 (App Router) · TypeScript strict · Tailwind v4
  src/
    app/                     routes: / (landing), /login, (app)/dashboard|new|projects/[id]|account
    components/              ui/ (primitives), landing/, upload/, app/
    services/                typed API client — the only place that talks to the backend
    lib/                     auth provider, env, formatting, presentation rules

  backend/                   pytest (real Postgres, real FFmpeg)

```

### Layer rules
| Layer | May import | Must not |
|---|---|---|
| `api/` | services, schemas, core, deps | contain business logic or raw SQL |
| `services/` | db, storage, media, schemas, core | import FastAPI |
| `pipeline/` | services, media, providers, storage, db | be imported by `api/` (enqueue via workers) |
| `media/`, `providers/` | core | touch the database |
| frontend `components/` | services, lib | call `fetch` directly |
| frontend `services/` | `api-types` (generated) | hand-write API shapes |

## 3. Conventions

* **Files:** TypeScript/React files are `kebab-case.tsx`; Python modules are `snake_case.py`
  (Python cannot import kebab-case). React components are `PascalCase`, TS functions
  `camelCase`, Python functions `snake_case`.
* **Types:** TypeScript `strict` + `noUncheckedIndexedAccess`; Python `mypy --strict`. No `any`.
* **Shared types:** change a Pydantic model → run `npm run gen:types` → commit `common/types`.
  CI fails if they drift.
* **Errors:** services raise `AppError` subclasses (`core/errors.py`); every error response is
  `{code, message}`. The frontend branches on `code`, shows `message`.
* **Tests:** every module has a matching test in `tests/`. Backend tests hit a real database
  and real FFmpeg; only the rate-limit counter is replaced.
* **No fake functionality:** no mock buttons, simulated progress or placeholder results.
  If a dependency is missing the UI says so.

## 4. Data model (PRD §9)

13 tables — the PRD's 12 plus `video_analyses`. Source data, AI decisions, intermediate outputs
and final assets are stored separately so the pipeline can be improved and re-run.

```
users 1─* projects 1─1 source_videos
               │ 1─* processing_jobs      (state, per-stage bookkeeping, lease, cost, retries)
               │ 1─1 transcripts 1─* transcript_segments (words with timestamps)
               │ 1─1 video_analyses        (structured full-video understanding)
               │ 1─* candidates            (scored clip proposals)
               │ 1─* clips 1─* clip_assets (only is_final=true assets are served)
users 1─* brand_presets · usage_records (credit ledger) · subscriptions
```

* Credits: `usage_records` is an append-only ledger; `users.credits_balance` is a cache kept in
  the same transaction. 1 credit = 1 minute of source video.
* All object keys live under `users/{user_id}/projects/{project_id}/` so deleting a project
  deletes every file.

## 5. Upload flow

1. `POST /projects` → project `CREATED`.
2. `POST /projects/{id}/upload` validates type/extension/size → signed PUT URL (size is signed).
3. Browser PUTs bytes to storage, showing real byte progress.
4. `POST /projects/{id}/upload/complete` → HEAD (exists, exact size) → ffprobe via signed URL
   (header only) → rules (has audio, 30 s – 4 h) → `UPLOADED`. Failures mark the upload
   `failed` with a user-readable reason.

## 6. Pipeline (Milestones 2–4)

Stages `INGESTING → TRANSCRIBING → UNDERSTANDING → SELECTING → EDITING → RENDERING →
QUALITY_CHECK → COMPLETED` (plus `FAILED`, `NEEDS_REVIEW`, `CANCELLED`). Each stage is
idempotent: it checks for its persisted output before running, so retries resume rather than
restart. A DB lease on `processing_jobs` stops two workers running one job; Celery
`acks_late` + `reject_on_worker_lost` re-queues work from crashed workers.

## 7. Decision log

| # | Decision | Why |
|---|---|---|
| 1 | Python package at `backend/src/clipmaker/` | standard src-layout; avoids top-level `api`/`db` import collisions |
| 2 | snake_case Python files | kebab-case modules cannot be imported |
| 3 | Pydantic → OpenAPI → TS types | one contract across two languages, no duplication |
| 4 | Added `video_analyses` table | keeps the large AI understanding output separate (PRD §9) |
| 5 | Local storage with HMAC-signed URLs in dev | same presigned-URL flow as R2, no cloud account needed |
| 6 | `/dev/token` login (dev only, refused in production) | develop/test without a Supabase project |
| 7 | Public `GET /plans` | landing-page pricing without duplicating the catalog in the frontend |
| 8 | Self-hosted fonts via `@fontsource` | `next/font/google` needs network access at build time |
| 9 | Rate limiter fails open if Redis is down | a limiter outage must not take the API down |
